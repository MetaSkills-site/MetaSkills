AI System Architecture

The MetaSkills application features a sophisticated, highly available multi-model AI architecture. The system relies on centralized prompt configurations, intelligent fallback cascading, and real-time NDJSON streaming architectures to guarantee up-time without compromising user experience. This document breaks down the core technical layers in detail.

1. The Prompting Engine & Routing Configuration

All AI requests begin by querying the central routing configuration file (config/aiPromptConfig.js) rather than hardcoding logic inside specific controllers. This promotes strict separation of concerns.

Dynamic Prompt Builders

Instead of static strings, prompts are dynamically generated via standardized arrow functions that take structured configurations (e.g. difficulty, topic). They also take anti-hallucination lists to strictly prevent outputting duplicate words. 

// aiPromptConfig.js:4
export const VOCAB_PROMPT_BUILDER = (count, difficulty, generated = "") => {
  let basePrompt = \`Generate \${count} English vocabulary words at a **\${difficulty}** difficulty level...\`;

  const hasGeneratedItems = Array.isArray(generated) ? generated.length > 0 : !!generated;
  if (hasGeneratedItems) {
    const generatedList = Array.isArray(generated) ? generated.join(', ') : generated;
    basePrompt += \`\n\n**CRITICAL — DUPLICATE PREVENTION (MANDATORY):**\nThe following words have ALREADY been generated. You MUST NOT include ANY of these words in your output... Blocklisted words: \${generatedList}\`;
  }
  return basePrompt;
};

Model Fallback Arrays

The getPromptConfig function pairs every endpoint mode with a hardcoded, prioritized array of diverse models. This guarantees that if one specific model or API parameter goes down, the backend instantly fails over.

2. Dynamic API Routing & The Graceful Fallback Pipeline

Instead of throwing 500 errors to the frontend when a model is overloaded, the system utilizes a modelsToTry iterative loop inside the genai.controller.js. The backend systematically advances down the queue until a successful HTTP 200 payload with valid JSON is parsed.

Multi-Vendor API Interoperability

The AI engine supports both Google's official @google/genai SDK and native REST integration with Nvidia's NIM API inside the same try-catch context. It detects the required routing protocol solely by checking the configured modelName string.

3. Real-Time NDJSON Streaming Architecture

Because generation and evaluation logic can take several seconds per API vendor depending on cluster load, standard REST architectures leave the frontend looking "frozen". MetaSkills solves this by enforcing a Multiplexed NDJSON Stream (Newline Delimited JSON) architecture.

Backend Interval Generation

Using HTTP Chunked Transfer Encoding, the backend immediately replies with an application/x-ndjson header and actively pumps simulated progress strings into the buffer every 2.5 seconds, while asynchronously awaiting the slow external LLM API logic. 

// genai.controller.js:318
  res.setHeader("Content-Type", "application/x-ndjson; charset=utf-8");

  const PROGRESS_STEPS = ["Analyzing sentence structure...", "Scoring usage correctness...", ...];
  let stepIndex = 0;
  
  // Pump simulated JSON progress down the socket actively
  progressInterval = setInterval(() => {
    if (stepIndex < PROGRESS_STEPS.length) {
       res.write(JSON.stringify({ type: 'status', message: PROGRESS_STEPS[stepIndex] }) + '\n');
       stepIndex++;
    }
  }, 2500);

Frontend Stream Decoding

On the frontend (e.g., MarathonSentencePractice.jsx), standard axios.post logic was ripped out and replaced with the native browser ReadableStreamReader. The frontend manually decodes and splits the stream frame-by-frame as bytes arrive over the wire, surfacing the live { type: 'status', message: '...' } strings dynamically into the React state variable before the final JSON object ever finishes generating.
